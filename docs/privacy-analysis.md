# APKForge Privacy, Tracker & Ads Intelligence (Phase F)

The APKForge Privacy Intelligence layer provides dedicated, inspectable, and evidence-backed analysis of privacy-relevant behaviors, third-party libraries, and advertising/tracking components within Android applications.

Phase F answers the fundamental question:
> **What data capabilities does this APK declare or exercise, which third-party SDKs and trackers are embedded, what network endpoints are configured, and what concrete static evidence supports each observation?**

---

## 1. Core Principles & Analytical Boundaries

Phase F enforces strict analytical rigor and neutral terminology. It explicitly separates observed facts from inferences and avoids speculative claims:

### Critical Concept Distinctions

| Concept | Definition | Invariant in APKForge |
|---|---|---|
| **Detection** | Identification of a known symbol, class name, string literal, or manifest element matching a catalog rule. | A detection identifies the presence of an artifact, not its runtime execution or maliciousness. |
| **Evidence** | Concrete, inspectable data points (file path, class name, method invocation, XML tag, byte offset, or string value). | Every finding must list exact `evidence_locations` and `evidence_values`. |
| **Inference** | Logical derivation of a capability from combined static indicators (e.g., manifest permission + framework API reference). | Inferences are explicitly tagged `is_direct=False` and `evidence_state=INFERRED`. |
| **Confidence** | Qualitative assessment of analytical certainty (`CONFIRMED`, `HIGH`, `MEDIUM`, `LOW`, `UNKNOWN`). | High confidence requires multi-source correlation (e.g. package namespace + specific class). |
| **Unknown** | Inability to evaluate a behavior due to missing metadata, unsupported structures, or external dependencies. | `UNKNOWN` is never collapsed into absence or assumed safe. |
| **Partial** | Incomplete extraction caused by size thresholds, corrupted sections, or degraded sub-analyzers. | Results and findings are explicitly marked `status=PARTIAL` and `analysis_completeness=PARTIAL`. |
| **Actual Network Behavior** | Dynamic transmission, receipt, or exfiltration of bytes over a network socket at runtime. | **Cannot be proven statically.** Endpoint presence does not establish runtime traffic. |

### Strict Neutrality Invariants
1. **No Pejorative Labeling**: An application or SDK is **never** labeled "malware", "spyware", or "malicious" merely because a tracker, permission, endpoint, receiver, or sensitive API is detected.
2. **No Privacy Score**: APKForge does not compute arbitrary pseudo-scientific scores (e.g. `42/100` or `Grade: D`).
3. **No Spyware Probability**: APKForge does not output probabilistic speculation (e.g. `87% probability of spyware`).
4. **No Safety From Absence**: The absence of detected trackers or sensitive APIs is never reported as proof that an APK is "safe" or benign.
5. **No Automatic Modification**: Phase F is an intelligence and analysis phase. It introduces no automated APK modification or stripping behavior.

## 2. Privacy Evidence Model

Every finding generated by the privacy layer adheres to the `PrivacyFinding` schema:

```python
class PrivacyFinding(BaseModel):
    id: str                                  # Stable finding ID (e.g. PRIV-CAP-LOCATION, PRIV-SDK-AD-ADMOB)
    category: str                            # Functional category (location, advertising, identifiers, etc.)
    title: str                               # Descriptive human-readable title
    description: str                         # Factual explanation of what was observed
    severity: Severity                       # INFORMATIONAL, LOW, MEDIUM, HIGH, CRITICAL
    confidence: Confidence                   # CONFIRMED, HIGH, MEDIUM, LOW, UNKNOWN
    evidence_state: EvidenceState            # OBSERVED, INFERRED, UNKNOWN, PARTIAL
    evidence_locations: list[str]            # Concrete locations (e.g. class:io.sentry.Sentry, manifest:service)
    evidence_values: list[str]               # Specific matched values or symbols
    source_component: str | None             # Component context if applicable (e.g. receiver name)
    related_permissions: list[str]           # Associated Android permissions
    related_domains: list[str]               # Associated network endpoints
    related_sdks: list[str]                  # Associated third-party SDK names
    is_direct: bool                          # True if direct static observation, False if inferred
    analysis_completeness: AnalysisCompleteness # COMPLETE, PARTIAL, UNKNOWN
    remediation_relevance: str | None        # Guidance for developers or auditors without modifying code
    evidence: list[Evidence]                 # Full provenance records with snippets
    limitations: list[str]                   # Analytical boundaries affecting this finding
```

### Explicit Evidence States
- **`OBSERVED`**: Concrete evidence exists directly in the APK bytecode, manifest, or resources.
- **`INFERRED`**: Capability deduced from static correlation between declared permissions and referenced framework APIs.
- **`PARTIAL`**: Evidence extraction was truncated or degraded (e.g., manifest declared permission without observed code reference).
- **`UNKNOWN`**: Indeterminate capability where static evidence is ambiguous or incomplete.

## 3. Third-Party Tracker & SDK Intelligence

APKForge maintains an auditable, declarative catalog of third-party SDK indicators in `src/apkforge/privacy/rules_data/`:

- **Advertising**: Google AdMob, Facebook Audience Network, Unity Ads, AppLovin, InMobi, ironSource, Vungle.
- **Analytics**: Firebase Analytics, Flurry, Mixpanel, Amplitude, Segment, CleverTap.
- **Attribution & Tracking**: AppsFlyer, Adjust, Branch Metrics, Kochava, Singular, Criteo, mParticle, OneSignal.
- **Telemetry & Diagnostics**: Sentry, Firebase Crashlytics, Bugsnag, Microsoft App Center.

### Rule Catalog Structure
Each catalog rule defines:
```yaml
- id: ad.google.admob
  name: Google AdMob / Google Mobile Ads
  vendor: Google
  category: advertising
  description: Mobile advertising platform for in-app monetization.
  evidence_requirements: Package namespace com.google.android.gms.ads or AdView class
  false_positive_risk: Low; specific to Google Mobile Ads SDK components
  source_reference: Google Mobile Ads SDK documentation
  packages:
    - com.google.android.gms.ads
  classes:
    - com.google.android.gms.ads.AdView
    - com.google.android.gms.ads.MobileAds
  domains:
    - googleads.g.doubleclick.net
    - pagead2.googlesyndication.com
```

### Static Network Use Determination
For every detected SDK, APKForge evaluates static network evidence and reports:
- **`actual_network_use_observed: False`** (static analysis cannot verify dynamic network transmission).
- **`network_use_status`**:
  - `CANNOT_DETERMINE_STATICALLY`: SDK bytecode classes are present, but no specific endpoint references were verified.
  - `STATICALLY_REFERENCED_ENDPOINT`: An endpoint associated with the SDK was found in bytecode/strings, but actual transmission remains unverified.
- **`network_use_determination`**: Factual statement explaining that static presence does not prove runtime data transmission.

## 4. Domain & Network Endpoint Intelligence

Building on Phase E network extraction, the `EndpointAnalyzer` categorizes all discovered endpoints:

| Category | Description | Example |
|---|---|---|
| `first_party` | Domain matches the application's root package name | `api.antennapod.org` in AntennaPod |
| `advertising` | Known ad serving and mediation hosts | `googleads.g.doubleclick.net` |
| `analytics` | Known analytics and behavioral event trackers | `api.mixpanel.com` |
| `telemetry` | Known crash reporters and diagnostic loggers | `o0.ingest.sentry.io` |
| `attribution` | Install attribution and deep linking endpoints | `app.appsflyer.com` |
| `cdn` | Content delivery networks and static asset hosts | `cdnjs.cloudflare.com`, `fastly.net` |
| `social_login` | Authentication and OAuth providers | `github.com`, `accounts.google.com` |
| `update_infrastructure` | Software update repositories and distribution | `f-droid.org`, `api.github.com` |
| `potentially_sensitive` | Raw IP addresses or unencrypted HTTP authentication endpoints | `http://example.com/api/v1/auth/login`, `192.168.1.50` |
| `unknown` | Endpoints without sufficient static evidence for categorization | `custom-backend.internal.net` |

Every endpoint finding preserves `raw_evidence`, `provenance` (e.g. `dex:classes.dex:offset=4096`), and the explicit disclaimer:
> *Presence of domain or URL in static binary does not prove data is transmitted to this endpoint.*

## 5. Permission + Component Correlation

The `PermissionAnalyzer` evaluates declared manifest permissions against static bytecode:
- **Strong Correlation**: Application requests `android.permission.ACCESS_FINE_LOCATION` and invokes `android.location.LocationManager.getLastKnownLocation`.
- **Declared Only (`DECLARED_ONLY`)**: Application declares `android.permission.RECORD_AUDIO` in `AndroidManifest.xml`, but no audio recording APIs (`AudioRecord`, `MediaRecorder`) appear in DEX bytecode.
  - Flagged as `PARTIAL` evidence with explicit uncertainty: *Permission declared in manifest, but actual runtime utilization remains uncertain.*
- **Component Correlation**:
  - `RECEIVE_BOOT_COMPLETED` correlated with `<receiver>` elements listening to `BOOT_COMPLETED`.
  - `BIND_ACCESSIBILITY_SERVICE` correlated with declared `<service>` components.
  - `BIND_NOTIFICATION_LISTENER_SERVICE` correlated with notification listeners.

## 6. Static Behavior Indicators

The `BehaviorAnalyzer` detects privacy-relevant API patterns across 13 distinct categories:
1. **Device Identifiers**: `getDeviceId`, `getImei`, `getSubscriberId`, `getSimSerialNumber`, `ANDROID_ID`.
2. **Advertising Identifiers**: Google Play Services `AdvertisingIdClient`.
3. **Location APIs**: `LocationManager`, `FusedLocationProviderClient`.
4. **Contacts APIs**: `ContactsContract`, address book content providers.
5. **Microphone / Audio**: `AudioRecord`, `MediaRecorder`, `SpeechRecognizer`.
6. **Camera Capture**: `android.hardware.Camera`, `android.hardware.camera2`.
7. **Clipboard Access**: `android.content.ClipboardManager.getPrimaryClip`.
8. **Accessibility Services**: Manifest services bound to accessibility events.
9. **Notification Listeners**: Manifest services reading incoming user notifications.
10. **WebView & Network**: `android.webkit.WebView`, cleartext HTTP traffic permissions.
11. **Background Scheduling**: `WorkManager`, `JobScheduler`, `AlarmManager`.
12. **Boot / Persistence Receivers**: Broadcast receivers registering for system startup.
13. **Dynamic Code Loading & Reflection**: `DexClassLoader`, `PathClassLoader`, reflection on sensitive classes.

## 7. Structured Privacy Report

Reports are rendered via `PrivacyReport` into both Markdown and JSON formats, strictly partitioned into eight standardized sections:

- **Section A: Permissions** (Declared counts, categorized breakdown, declared-only uncertainty).
- **Section B: Components & Capabilities** (Background services, boot receivers, accessibility, notification listeners).
- **Section C: SDK & Library Indicators** (Trackers, advertising, analytics, telemetry, static network status).
- **Section D: Domains & Endpoints** (Categorized endpoint inventory, first-party vs third-party, network disclaimer).
- **Section E: Sensitive API Indicators** (Device IDs, AAID, clipboard, reflection, dynamic loading).
- **Section F: Correlated Findings** (Full list of prioritized findings with evidence locations, values, and remediation relevance).
- **Section G: Unknown / Partial Analysis** (Inconclusive items, declared-only permissions, unclassified endpoints).
- **Section H: Evidence Limitations** (Explicit static analysis boundaries, disclaimers, and toolchain metadata).

## 8. Cross-Check with Phase B Security Analysis

Phase F provides programmatic cross-checking against Phase B security results via `compare_privacy_with_security(privacy_res, security_res)`:
- **Overlapping Findings**: Findings identified by both analyzers (e.g. boot persistence receivers).
- **New Privacy Findings**: Additional intelligence discovered by Phase F (trackers, analytics, classified endpoints).
- **Strengthened Findings**: Security findings substantiated with additional static code references.
- **Incomplete Evidence**: Security findings where Phase F observed that declared permissions lack matching bytecode calls.
- **Discrepancies & Explanations**: Systematic explanation of different classification criteria (e.g., Phase B flagging an SDK under potential attack surface vs Phase F categorizing it as an advertising library without inferring malicious intent).

## 9. Programmatic API & CLI Usage

### Programmatic API
```python
from pathlib import Path
from apkforge.privacy.service import PrivacyAnalysisService
from apkforge.security.engine import SecurityEngine

apk_path = Path("sample.apk")

# 1. Execute static privacy analysis
result = PrivacyAnalysisService.analyze(apk_path)

# 2. Generate structured report
report = PrivacyAnalysisService.generate_report(result)
markdown_text = report.to_markdown()
json_dict = report.to_json()

# 3. Cross-check against Phase B security findings
security_result = SecurityEngine().analyze(apk_path)
comparison = PrivacyAnalysisService.compare_with_security(result, security_result)
```

### CLI Command
```bash
apkforge privacy path/to/app.apk
apkforge privacy path/to/app.apk --json
apkforge privacy path/to/app.apk --report artifacts/privacy-report.md
apkforge privacy path/to/app.apk --report artifacts/privacy-report.json
```

**ANSI-Free Guarantee**: The `--json` flag emits raw, deterministic JSON directly to `stdout`. It is tested to remain 100% free of ANSI color codes even when environment variables such as `FORCE_COLOR=1` or `FORCE_COLOR=3` are present.
